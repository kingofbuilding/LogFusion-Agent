# Agent MVP 设计与评估规划

核心侧重点是告警后的自主调查与证据关联。

## 已实现结构

- events.py：允许字段投影、时间归一化、实体提取、稳定事件 ID。
- tools.py：六种只读工具、证据收集、查询边界与案例分离。
- planner.py：离线剧本与 LLM 工具调用两种规划器。
- engine.py：执行预算、循环控制、已查证据关联与结果导出。
- adapters.py：原检测与向量 RAG 的延迟加载适配。
- frontend/agent_app.py：独立及嵌入式调查工作台。

LLM 决定查询路径，报告受 SSH 证据规则约束；当前不是通用自治 SOC。

## 后续评估（尚未执行）

比较：原固定检测+RAG+报告、固定 SSH 工具剧本、LLM 动态调查。

保持日志、工具权限和预算一致，评估事件结论准确率、证据引用正确率、无依据结论比例、调查覆盖、调用次数、token、延迟。对不同模型多次运行，披露失败、超时及截断。

准备人工事件级事实与证据引用。攻击标签只供评估器使用，不进入工具。按事件/时间隔离测试集，案例不得包含测试事件答案。

## 迭代顺序

3. 持久化状态、取消恢复、预算细化与真实服务兼容验证。
4. 人工标注事件级评估，随后扩展 Web 等调查场景。
